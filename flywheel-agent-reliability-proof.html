A state machine that makes unsafe work visible.

A small, inspectable protocol instead of an opaque agent loop. Each stage emits a trace event and can stop the run.

type ToolReceipt = {
  state: "verified" | "held" | "quarantined";
  trace_id: string;
  cost_usd: number;
  latency_ms: number;
}

Non-negotiable guardrails

  • Tool allowlist and JSON-schema validation precede execution.
  • Any non-read action enters a human approval gate with a rendered diff.
  • Stable action and idempotency keys make replay duplicate-safe.
  • Injection-like directives are separated from trusted task input and quarantined.
  • Retry budget is bounded; exhausted jobs land in a reviewable DLQ.
  • No financial, betting, custody, or external-send action appears in this proof.

Founder-readable failure atlas

Name the failure before it names you.

Each entry defines a practical failure mode, observable signal, and a narrow control. This is illustrative architecture, not a client audit.

5 priority patterns

Cross-tenant context leak

CRITICAL

Signal: a tool request contains a tenant ID inconsistent with the authenticated run envelope.

CONTROL: bind tenant scope server-side; reject a mismatched envelope before planning.

Prompt injection changes intended tool use

CRITICAL

Signal: untrusted content asks to ignore policy, reveal instructions, or expand authorization.

CONTROL: classify as untrusted data; quarantine, preserve evidence, and require a human decision.

Duplicate execution after timeout

HIGH

Signal: a client retry arrives with an existing stable action key but uncertain adapter completion.

CONTROL: lock on idempotency key, return stored receipt, and reconcile asynchronously.

Transient tool error loops forever

HIGH

Signal: repeated adapter errors exceed a retry budget or latency ceiling.

CONTROL: exponential backoff with jitter, capped attempts, then DLQ plus an actionable receipt.

Schema-valid but incomplete result

MEDIUM

Signal: output parses yet misses a required evidence reference or verification predicate.

CONTROL: enforce semantic postconditions and mark the run incomplete rather than successful.
